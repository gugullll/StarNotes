# StarNotes

节点式可视化笔记：**画布就是主界面，节点就是知识点**。笔记是普通 Markdown 文件，
存在你自己指定的文件夹里——程序在别处不留任何副本，关掉网页它们还在。

- **画布 = 文件夹**，可以一层层套下去，层数不限
- 手动连线表达关系（属于 / 前置知识 / 对比…），点节点上的 `+N` 展开相邻知识
- 笔记文件零 frontmatter：第一行就是 `# 标题`，这一篇可以单独发给任何人
- 四套配色（含深色），选择只存本机，不进笔记库
- 可选绑定 GitHub 仓库：整份推送 / 拉取、读提交历史、回退到任意一版
- **无构建、无依赖、无后端**：没有打包步骤，打开 `index.html` 就能用

需要 Chrome / Edge（依赖 File System Access API）。数据始终在你自己的磁盘上。

## 打开方式

```bash
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000
```

> 建议用本地服务而不是双击 `index.html`：文件系统接口在 `file://` 下的行为在不同 Chrome 版本里不稳定。

## 第一次启动必须先选文件夹

打开后是一道闸门，**不选文件夹进不去**。没有默认位置，也没有内置示例库——你指定哪个文件夹，笔记就写在哪里，程序在别处不留任何副本。

先新建一个专用空文件夹（例如 `文档/StarNotes`）再选它。**文件夹里已有的 `.md` 会被全部当作笔记载入**，所以别选装满杂项 Markdown 的目录。

选完之后，顶栏面包屑的第一格就是这个库的名字；想换一个文件夹，点顶栏的「选择笔记目录」（按钮上悬停会显示当前是哪个目录，免得误点）。

需要 Chrome / Edge。Safari、Firefox 没有 `showDirectoryPicker`，会停在提示页，无法进入。

浏览器重启后权限常常要再确认一次，此时闸门会变成「继续上次的库」，点一下按钮直接回到原文件夹——文件不会被动过。

## 画布 = 文件夹，可以一直套下去

**一个文件夹就是一块画布，也就是上一层图里的一个节点。** 层数不限：

```
你选的库/                 ← 根画布（顶栏面包屑的第一格）
├── 知识地图/             ← 子画布
│   ├── 双链与反链.md      ← 笔记
│   ├── 知识图谱.md
│   └── 图谱/             ← 孙画布，和笔记同层并存
│       └── 三层笔记.md
├── 写作线索/
└── 灵感.md               ← 根画布自己的笔记
```

- 任意一层的图里，节点 = 该层的「子文件夹（画布）+ `.md`（笔记）」，两种同层共存，可以互相连线。
- **关系只在本画布内有效**：画布里的边记在这块画布的 `StarNotes.graph.md`，画布之间的边记在上一层的关系表。所以「A 画布 → B 画布」和「A 里的某篇笔记 → A 里的另一篇」互不干扰。
- 顶栏面包屑显示完整路径，点任意一级直接跳回去；`⌘/Ctrl + ↑` 回上一层。
- 双击画布进入；hover 画布 320ms 弹出预览卡：缩略图 + 子画布清单 + 笔记清单 + 关联数。
- 右键画布：进入 / 在里面新建笔记 / 在里面新建子画布 / 重命名 / 删除（递归删掉整个文件夹）。
- 「＋ 笔记」和「＋ 画布」都建在**当前这一层**，不会跑到根目录去。

> 早期版本只有两层（库根 = 画布列表，画布 = 笔记列表），现在统一成递归结构。旧库打开后行为不变——原来的画布文件夹仍然是一块画布。

### 一张节点卡片上有什么

```
双链与反链                     ← 标题，取自正文的 H1（最多两行）
双链与反链.md                  ← 磁盘上真正的文件名（等宽字体。画布没有这一行：
                                 它的名字就是文件夹名，和标题永远相同）
3 关联  +2                    ← 关联数 + 展开隐藏相邻的入口
```

两个名字都要露出来，因为它们**不一定一样**：标题里的 `\/:*?"<>|` 在落盘时会被洗成 `-`，重名的第二篇会变成 `xxx (2).md`，别人放进文件夹的 md 也可能是 H1 和文件名不同。搜索框两个名字都认——搜 `(2)` 能直接找到那一篇。悬停卡上也会写一遍文件名。

新建的笔记和画布都不会和已有节点重叠：先按「视口中心」（或双击的位置）试放，被占了就从该点起顺时针由内向外找最近的空位。所以连点几次「＋ 笔记」得到的是一圈排开的节点，而不是叠在一起的一个。

## 外观：四套主题

顶栏的 `主题` 按钮（启动页上也有一个「换一套配色」）打开外观面板：四张带预览的卡片，**点一下立刻生效**，没有「保存」按钮，也不用刷新。

| 主题 | 底色 | 强调色 | 什么时候用 |
|---|---|---|---|
| 纸白（默认） | 米白纸面 | 靛紫 | 白天、投影，最中性 |
| 暖纸 | 旧书页暖调 | 赭石 | 长时间读，比纯白柔和 |
| 夜蓝 | 近黑深蓝 | 浅紫 | 晚上开着不烧眼 |
| 苔绿 | 冷调灰绿 | 墨绿 | 白天用，比纸白安静 |

- 选择存在 `localStorage` 的 `starnote.theme`：**不进笔记库、不进 Git、不同步给别人的机器**。换台机器要重新选一次——显示偏好不该跟着笔记内容走。
- 首屏之前由 `index.html` 头部的一小段内联脚本先把 `data-theme` 套到 `<html>` 上；不这么做，深色主题会先闪一帧白底。
- 实现上只换一层 CSS 变量：组件样式里**不出现写死的颜色**，全部 `var(--x)` 取色。加一套主题 = 在 `style.css` 加一个 `[data-theme="x"]` 块 + 在 `theme.js` 的 `THEMES` 加一行（预览色也要填，测试会核对它和 CSS 一致）。
- 测试守着的四件事：每套主题都把 `:root` 的颜色变量补齐（漏一个，就有元素不跟着换）、主题块之外没有写死的色值、卡片预览色等于实际取值、`theme.js` 必须是 IIFE（`app.js` 是普通脚本，同名顶层 `const` 会直接 SyntaxError、整页白屏）。
- 面板开着时键盘归面板管：`Esc` 只关面板不清选择，`Del` 不会删掉背后的笔记。

顺手修掉的两个「不跟主题」的老问题：关系连线的**箭头**颜色原来写死在 HTML 的 `fill` 属性上，改成 CSS 变量；关系**标签**的圆角底板从来没有样式，`rect` 吃的是 SVG 默认的纯黑填充（一直是个黑块），现在是卡片底色 + 细描边 + 强调色文字。

## GitHub：绑定与同步

顶栏的 `GitHub` 按钮 → 填五项 → 点「校验并绑定」。浏览器里跑不了 git，所以走 GitHub REST API：一个 token + 一个 `owner/repo` 就是全部凭据。

| 字段 | 说明 |
|---|---|
| 仓库地址 | `owner/repo`、`https://github.com/owner/repo`、`git@github.com:owner/repo.git` 都认；多出来的 `/tree/main` 会被忽略 |
| 分支 | 默认 `main` |
| Token | fine-grained PAT，权限 `Contents: Read and write`，并且把该仓库加进 Repository access |
| 作者名 / 邮箱 | 提交时用。邮箱填 GitHub 账号上的邮箱，提交才会算到你名下 |

校验按顺序查五件事，每一步失败都直接给「为什么 + 怎么办」：

1. **本地字段**——地址能不能解析、分支/token/作者/邮箱填对没有。这一步不发请求，省一次往返
2. **`GET /user`**——token 还有效吗、是不是过期了、是不是被限流（403 且剩余次数为 0）
3. **`GET /repos/{owner}/{repo}`**——仓库在不在、token 有没有它的权限、仓库是不是已归档
4. **`POST /git/blobs`（写探测）**——**真的写一次**，见下面那节。这一步才能回答「token 能不能推送」
5. **`GET /repos/{o}/{r}/git/ref/heads/{branch}`**——分支在不在；404 时再列一遍现有分支告诉你该填哪个；空仓库（一个分支都没有）单独放行，并记为「第一次推送会建分支」

绑定成功后顶栏按钮变成 `owner/repo` 加一个绿点；信息存在 IndexedDB（`starnote-gh`），点按钮可以改配置或「解除绑定」。校验失败不会动原来那份绑定。

面板里的进度会按步显示 `Token ✓  仓库权限 ✓  写权限 ✓  分支 …`，卡在哪一步一眼看得出来。

### 为什么校验要真的写一次：`403 Resource not accessible by personal access token`

推送时最常见的失败是这个 403，它的意思是 **token 没被授予写权限**（不是文件有问题，也不是网络）。这个 403 藏得很深，因为：

`GET /repos/{owner}/{repo}` 返回的 `permissions.push` **反映的是「你这个人对这个仓库有没有写权限」，和 token 被授予的 Contents 权限是两层东西**。只读的 fine-grained token 在这里照样看到 `push: true`，一路绿灯通过校验，直到第一次 `POST /git/blobs` 才炸——而那时候用户已经填完五个字段、点了绑定、还以为是网络问题。

所以校验最后加了一步真写入：`POST /git/blobs` 建一个 26 字节的固定探针（`StarNotes write probe`）。它不进 tree、不进 commit、仓库页面上看不见，也不计入仓库大小；因为内容固定，sha 也固定，反复探测永远只有一个悬空对象，成本就是一次请求。

**测出只读不阻断绑定**：读是通的，拉取现在就能用。只是顶栏悬停标「Token 只读，不能推送」、面板给一条黄条说明、同步区把推送按钮直接关掉——不用人点一次、吃一次 403 才知道。

修的办法（不用换 token）：fine-grained 去 token 设置页把 Repository permissions → **Contents** 改成 **Read and write**；classic 勾上 **repo**。保存后回来点「校验并绑定」，标记会自动清掉。只有页面只给 `Regenerate` 的时候才需要生成新的。

写权限探测问不出来的时候（网络抖、限流）**不会**被当成只读——那只是「没测出来」，留到推送时再见真章。

### 网络抖一下的时候

这些请求是顺序发的，任何一个没拿到响应都会自动重试一次（首次 10 秒超时，重试放宽到 15 秒）。4xx 不重试——GitHub 已经明确拒绝了，再来一次也一样；5xx 才重试。失败文案会点名是哪个端点、等了多久、重试过几次，**不会再把裸的 `HTTP 0` 丢出来**：

- `连 GitHub 超时（/repos/owner/repo/git/ref/heads/main）` → 这个请求 15 秒没响应，自动重试了 1 次
- `连不上 api.github.com（…）` → 如果前一个请求刚成功过，会明说「网络应该没断，更像是这一条被拦住了（浏览器扩展、代理规则、安全软件）」，而不是让人去查网络

**分支这一步有降级**：如果前两步已经确认 token 有效、仓库可写，只有分支那一步卡在网络，就照样绑定——顶栏悬停里标一句「分支未确认」，面板里给一条黄条说明，且不会自动收起。绑定真正要确认的是「凭据对不对、能不能写」，分支名留到第一次推送时再见真章，不该因为一次 GET 超时把人挡在门外。网络恢复后重新点一次「校验并绑定」，这条标记就会消失。

### 一个踩过的坑：仓库级接口必须带 `/repos/{owner}/{repo}`

`GET /git/ref/heads/{branch}` 这种写法是错的，分支校验一开始就因此完全失效：GitHub 对这条不存在的路径返回 404，而且 **`OPTIONS` 预检响应里没有 `Allow-Headers` / `Allow-Methods`**，浏览器判定预检失败，`fetch` 直接抛 `TypeError: Failed to fetch`——JS 拿不到任何状态码，于是被当成「连不上网」，提示成了网络问题。

正确写法是 `GET /repos/{owner}/{repo}/git/ref/heads/{branch}`（`git/refs/heads` 同理）。教训是：假 fetch 的路由如果只匹配路径后缀，就会把这个 bug 一起「测过」；现在测试里有一条路径守卫，任何请求只要不在 `/repos/{owner}/{repo}/` 下面就直接失败。

### Token 过期了会怎样

fine-grained token 必须设过期时间，所以「某天突然同步不了」是必然会遇到的事。这里让它提前可见：

- **读到期日**：GitHub 没有查询 token 详情的端点，但任何已认证响应都带 `GitHub-Authentication-Token-Expiration` 头（classic 是 `… UTC`，fine-grained 是 `… +0100`），绑定时顺手存下来。
- **打开网页就查一次**：`GET /rate_limit`——这个端点不消耗配额，正好用来问「token 还活着吗」。6 小时内不重复问，断网时不会误判。
- **三档提示**：剩 7 天内 → 按钮变黄，悬停写「还有 3 天到期」；已过期或返回 401 → 按钮直接写 **Token 已过期**（红），点开面板把光标放到 Token 格，只要求换 token，其他字段不用改；没到期却被拒 → 判定为「被删除或被重置」，单独给一句话。
- 失败原因也分开了：401 时如果本地记着到期日且已过，就说「Token 已于 2026-12-01 过期」，否则说「被拒绝了」，不再一律糊成「无效或已过期」。
- **一个已知的上游 bug**：fine-grained token 有时把「服务器当前时间」当成到期时间返回。这种值永远贴着眼下的钟，所以离现在不到 5 分钟的一律当作「读不到」，退回 401 判断，避免每次打开都误报。

**关于 token**：它等同密码，所以只存本机 IndexedDB——不进 URL、不写进库文件夹（避免被 `git add` 一起提交）、界面上只出现打码形式（`github_pat_…abcd`）。`github.js` 里所有请求都带 `Authorization: Bearer`，没有任何数据发往第三方。

## 同步：只有推送和拉取，都是整份覆盖

**不做合并。** 点开面板会自动比对一次，把差异分三类摆出来，你只需要选方向：

| 分类 | 推送 | 拉取 |
|---|---|---|
| 只在本地 | 上传 | **删掉本地这些** |
| 只在远端 | **删掉远端这些** | 下载 |
| 内容不同 | 用本地覆盖 | 用远端覆盖 |
| 两边一致 | 跳过 | 跳过 |

没差异时两个按钮是灰的；有删除项时，确认框会把文件名一条条列出来——「覆盖」的前提是你知道什么会消失。

**推送**走 Git Data API 四步：`POST /git/blobs`（每个改动文件一个，并发 4）→ `POST /git/trees`（`base_tree` 指向上一次提交的树，只列改动，删除项写 `sha: null`）→ `POST /git/commits`（`parents` 是当前 head）→ `PATCH /git/refs/heads/{branch}`（`force: false`，这期间别人推过会返回 409，重来一轮即可）。空仓库分支还不存在，改走 `POST /git/refs` 建。

**拉取**是 `ref → commit → trees?recursive=1` 拿到整棵树的 `path + sha`，只下载 sha 和本地不一样的文件，再删掉本地多出来的。删空的文件夹一并清掉，否则远端删掉一块画布后本地会留一个空画布。

**首次推送有保护**：从没同步过时，远端多出来的文件默认**不删**（面板上一个勾选框，默认勾上）。因为「本地覆盖远端」如果第一次就把仓库里的 README 之类清掉，人会懵。取消勾选才按覆盖语义删。

**只碰 `.md`**：图片、`.gitattributes`、`.github/` 既不读也不写不删，误删的爆炸半径就限定在笔记范围内。反过来，仓库根的任何 `.md` 也算笔记——把库推到有 README 的仓库根之前，先在本地想清楚。

**比对不用 mtime**：GitHub 给的是 blob sha（`sha1("blob " + 字节数 + "\0" + 内容)`），本地用同一个算法算一遍，相等就是内容相同。mtime 会被复制、解压、换编辑器改掉，内容哈希不会。读文件时统一把 CRLF 折算成 LF，否则 Windows 上被别的编辑器存过一次的文件会永远显示「两边都不同」——哈希变了，但内容没变。

**拉取前会存快照**：本地没有 `.git`，被覆盖就找不回来。所以拉取前（以及「回退到某一版」前）把整库正文存进 IndexedDB（保留最近 3 次），面板上有「恢复上一版」。它其实是来回切换：恢复之前也会把当前状态存一份，点两次能回到原处。推送不留快照——远端旧内容在 git 历史里，本来就不会丢。

**已知不做**：不合并；不支持勾选单个文件同步（那就变成合并了）；不做后台自动同步（自动拉取和正在编辑的冲突是最难解释的故障）；不支持推到仓库子目录（推到分支根）；空文件夹不会被同步（git 存不了空目录）。

### 提交历史与回退

面板上的「历史」读 `GET /repos/{o}/{r}/commits?sha={branch}&per_page=20&page=n`，一页 20 条，底部「加载更早的 20 条」翻页。每条显示说明首行、`短 sha · 时间 · 作者`，当前 head 标「远端最新」，前缀是 `StarNotes:` 的提交另有标记（一眼分出哪些是这台机器推的）。

**选一版 → 先看差异 → 再回退**。点一行会用 `GET /git/commits/{sha}` → `trees?recursive=1` 把那一版的 `.md` 列表拉下来，和现在比一遍，底栏写「新增 / 本地多出 / 改写」各多少。回退按钮才解锁——这样点下去之前你已经知道会多出什么、丢掉什么。

**回退只改本地，远端分支一动不动**（代码里没有任何 `PATCH`/`POST`）。想让 GitHub 也回到那一版，回退后点「推送 →」：那会生成一个**新提交**，历史一条都不会少。不做 `force push`——抹掉提交是唯一真正不可逆的操作，一次手滑就再也找不回来。

回退前同样存快照，所以「恢复上一版」能把这次回退整个撤掉（再点一次又切回去）。差异区会挂一条提示：本地已回退到 `abc1234`，远端最新还是 `def5678`，提醒你「还没推」。

**这一版里没有的文件**默认一起删（否则画布上会留着一堆这一版不存在的节点），底栏有勾选框可以改成保留。当前层的 `StarNotes.canvas.md` 会被删掉、然后由程序按这一版的文件重排坐标——这是它作为「这层布局」的本分。

### 提交信息：自动生成，可以改

推送区上方的说明框在比对完成后自动填一条：

```
StarNotes: 同步笔记（+2 ~1 -1）

· 新增 两张卡片.md、画布.md
· 修改 双链与反链.md
· 删除 旧稿.md
```

推送时用它当 `commit.message`。**一旦手改，「比对」就不再覆盖它**（被自动刷新冲掉手写内容是最恼人的那种 bug），右上角标记从「自动」变「已手改」；点「重写」回到自动那条。清空也会退回自动——绝不往 GitHub 推一条空说明。

## 文件格式

每一层（每个文件夹）各自有一份坐标表、一份关系表，加上纯笔记：

```
知识地图/
├── 双链与反链.md          ← 纯 Markdown 笔记
├── 知识图谱.md
├── StarNotes.canvas.md    ← 这层的坐标
├── StarNotes.graph.md     ← 这层的关系
└── 图谱/                 ← 子画布，自己再带一套这两张表
```

**一篇笔记一个 `.md`，是彻底的纯 Markdown**——没有 frontmatter、没有 id、没有关系。第一行是标题，剩下全是正文：

```markdown
# 双链与反链

正向链接是你主动写的引用，反向链接是系统告诉你「谁提过我」。
```

所以这个文件可以原样发给任何人，对方用任何 Markdown 编辑器打开都正常，不会看到一堆指向你本地其他笔记的 id。

**本层共用一张关系表 `StarNotes.graph.md`**，边全在这里（`##` 是出发节点，一行一条边；画布也可能是出发节点）：

```markdown
---
type: starnote-graph
version: 1
---

## 双链与反链.md
- 知识图谱.md | 前置知识 | →
- 语义网络.md | 相关 | ↔
```

- `→` 有向，`↔` 双向；中间那段是关系名，可以省略。
- 增删笔记不用动任何别人的文件，改这一张表就够了。
- 反向关系（谁引用了谁）由这张表直接推导，不需要全库扫描。

**本层一张 `.canvas.md`**，只记录「哪个节点、摆在什么坐标」（画布本身也用文件夹名当节点名）：

```markdown
---
type: canvas
id: c9f8e7d
name: 知识地图
---

- 双链与反链.md 1200 500
- 知识图谱.md 900 640
- 图谱 900 380
```

- **文件名就是笔记的身份。** 改标题会同时改文件名、关系表里的引用、坐标表里的引用，旧文件删除。
- 没有出现在坐标表里的节点 = 还没上板，点相邻节点的 `+N` 徽章（或右键「展开关联」）才会被摆出来。
- 关系与坐标无关：换画布（换个文件夹）只换一套坐标，笔记内容不动。
- **`*.canvas.md` 和 `*.graph.md` 一律算程序自己的文件，不会当笔记显示。** 早期版本把坐标分散成 `<画布名>.canvas.md`（比如 `主画布.canvas.md`），这类旧文件在打开时会只被读取坐标并并入本层的 `StarNotes.canvas.md`，原文件不动——确认没问题后可以手动删掉。

## 已知限制

- 只在 Chromium 内核验证过。没有 `showDirectoryPicker` 的浏览器（Safari / Firefox）直接停在启动提示页，不存在降级路径。
- 改标题是「写新文件 → 删旧文件」两步，不是原子操作，中途崩溃会留下重复文件。
- 改画布名要递归复制整个文件夹（浏览器接口没有「移动目录」），大画布改名会明显卡一下，空间也要够两倍。
- 「移入画布」同样是复制后删原件，不是原子操作；把大画布拖进另一个画布时会卡一下。移入时如果目标里已有同名笔记，会自动改名成 `名字 (2).md`，不覆盖。
- 在资源管理器里直接改文件名/文件夹名，会让关系表和坐标表里的引用失效（旧的 id 方案没这问题，换取的是笔记文件彻底干净）。
- 每进一层都会读一遍该层所有笔记的正文，层数深、笔记多时进入会变慢；懒加载和索引缓存都还没做。
- 全部节点用 DOM 渲染，约 1500 节点以上需要换成 Canvas/WebGL 渲染（sigma.js、G6）。
- 画布没有缩略图导航、没有分组框、没有跨层搜索（搜索只搜当前层）。
- 多选只作用于「当前层还在板上的节点」：拖动被选中的节点时只有被抓住的那一个会动（不做整组平移）；多选也不跨层、不能框选（橡皮筋选择还没做）。
- 批量删除是逐个删、逐个落盘，不是事务：中途失败会停下并报出没删掉的名字，已经删掉的不会回滚。
- GitHub 同步只有「覆盖」语义：两边都改过同一个文件时不会合并，也没有逐文件选择、没有部分推送，只能整份覆盖。
- 同步是逐文件请求：一篇一个 blob（并发 4），几百篇的库要几百个请求。GitHub 认证后 5000 次/小时够用，但没有进度条之外的分批续传，中途断网要从头再来一遍。
- 同步范围是整个库根（推不到仓库子目录），空文件夹不会同步（git 存不了空目录），非 `.md` 文件不参与。
- 拉取快照存在 IndexedDB 里，只保留最近 3 次；清浏览器数据就等于把这份「撤销」一起清掉。
- 历史版本只能整库回退到某一版，不能「只回退这一个文件」；列表里也看不到每条提交具体改了哪几篇（要多一次请求，先没做）。回退本身改本地、不改远端，所以严格说不是 `git revert`，是把树迁回去再让你决定要不要提交。
- 过期提醒只在你打开页面或点开面板时发生，没有系统通知、没有后台定时器（页面关着就什么都不做）。
- 没有 undo 栈（只有拉取/回退前的快照可回退）、没有多端并发冲突处理——两边同时改就是后推的那个人赢。

## 开发

没有构建步骤，改完直接刷新页面。测试需要 Node 和 jsdom（**只有测试需要，运行时零依赖**）：

```bash
npm install
npm test        # 在 jsdom 里跑约 390 条断言
```

改代码前建议先读 `app.js` 顶部的注释和各节的分节标题——那些"为什么这么写"的约定都写在代码旁边，
而不是集中在文档里。几个容易踩的地方：`--node-h`（CSS）与 `NH`（JS）必须相等、文件读写只用当前层句柄、
换层前先 `flushWrites()`、GitHub 仓库级端点必须带 `/repos/{owner}/{repo}`。
